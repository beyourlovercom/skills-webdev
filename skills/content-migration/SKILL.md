# S5 — Old content inventory and substantial rewrite

**Scope:** Shared, public workflow. Verify live project facts first; generated site-specific `skills/content-migration/SKILL.md` in the destination project's repo takes priority. No credential, real customer data or private commercial report belongs here.

## Input
Authorized legacy posts, old URLs/media licensing, GSC history, target brand, migration/coexist classification.

## Procedure
1. Inventory every relevant article with traffic/quality/freshness and source access, mark keep/merge/update/new-research/retire.
2. Preserve source attribution, rights and distinct positioning. Parallel sites must not mass republish trivial synonym swaps; migration should protect search intent, URLs and approved redirect mappings.
3. Prepare unique researched drafts and editorial change sets for WWW, verify facts, internal links and product alignment.
4. Batch high-impact content actions with separate approval; use checkpoints, previews and rollback logs.

## Gate
Copyright, brand isolation, uniqueness, search intent and editorial approval verified. No bulk publishing or deletion without authorization.

## Acceptance record
Always report host/device, evidence references, exact Git SHA, executed tests and PASS/FAIL/OPEN, approval state, no-production effects and next bounded action. Never confuse this Markdown document with an executable integration.
