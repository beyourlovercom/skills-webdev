【工作要求】

一、先确认 GSC 数据、网站身份和分析范围
1. 优先使用我提供的成熟 Skills、已授权连接器或可访问的 GSC 数据读取能力；按 Skill 的实际说明操作。先核对可读取的 GSC 属性（Domain Property 或 URL-prefix Property）、验证域名及 www/非 www、http/https 关系，禁止误用其他站点属性或拼接不同属性数据。
2. 优先分析最近 12 个完整月份，并尽可能对比上年同期。GSC 常规搜索表现历史通常只保留约 16 个月；若无法取得完整 24 个月可比数据，明确注明限制，改用共同可比月份、季度或环比，不得编造同比。
3. 核对 GSC 报表日期时区（通常为太平洋时间）、搜索类型（Web / Image / Video / News 等）、日期、查询过滤器、品牌词口径、国家、设备以及数据导出时间。不同搜索类型单独统计，不能简单相加冒充网站总搜索表现。
4. 检查数据质量：查询匿名化、隐私过滤、行数/导出限制、维度组合导致的总量差异、最近日期未完全入库、属性覆盖不完整、canonical 归属、迁移期间的数据拆分。明确页面或关键词缺行不等于零展示。
5. 如果有权限，读取“搜索结果表现”“网页索引/Pages”“站点地图”“Core Web Vitals”“HTTPS”“结构化数据/增强功能”等相关报告；对无法通过所用 Skill/API 读取的页面，标记未核实，不能假装已检查。
6. 若无法直接读取 GSC，先列出需要的授权方式或最小导出清单：搜索表现按日期、查询词、页面、国家、设备的导出；索引、Sitemap、CWV 和增强功能的可用导出/截图。说明每份文件需要的时间范围和筛选条件。没有数据时不要编造点击、展示、CTR、排名或收录情况。
7. GA4、Google Ads、询盘/CRM、订单、关键词工具和网站源码可以作为交叉验证，但必须分别列出来源、账号/属性范围、时间段及权限状态；没有其他权限时先完成 GSC 可完成的分析。

二、全面分析旧网站自然搜索表现
至少覆盖下列方面；每项提供实际数据、日期范围、分组依据、同比/环比（在有可比数据时）及明确判断：
1. 整体搜索趋势：点击、展示、CTR、平均排名，月度/周度变化与突增突降，区分流量变化和数据异常。
2. 搜索词结构：品牌词与非品牌词、产品词、采购/批发词、问题/教程词、商用意图词；区分信息型、商业调研型、交易/询盘型意图。
3. 关键词机会：高展示低 CTR、排名较好但点击不足、排名 4–10 或 11–20 且有商业价值、增长词、流失词、长尾词；说明机会判断方法，不把平均排名直接理解成固定排名。
4. 页面表现：首页、产品分类页、产品详情页、方案/行业页、落地页、博客/指南、联系方式页；列出主要查询词与对应 URL，以及页面表现变化。
5. 关键词与 URL 对应：同一关键词由哪些页面获取展示/点击，检查可能的关键词内耗、错误落地页、搜索意图不匹配、canonical/URL 迁移混乱；只有在证据充分时才判断互相竞争。
6. 国家、语言及设备：对重点目标市场分别分析查询词、页面、点击、展示、CTR、平均排名及移动/桌面差异，不将全球平均值套用于单个国家。
7. 搜索结果展现：有证据时分析搜索外观、富结果、图片/视频搜索及相关结构化数据；无报表时注明未核实。
8. 收录与技术 SEO：索引页面与未索引原因、重复页、canonical、重定向、404/服务器问题、Sitemap、robots/noindex、CWV、HTTPS。区分 GSC 报告事实与需要源码/抓取才能验证的猜测。
9. 内容增长与衰退：识别持续贡献流量、近阶段新增长、严重下滑、内容老化、搜索意图错位及薄弱主题；不得仅凭相关性认定算法更新导致下降。
10. SEO 商业价值：结合可获得的 GA4、真实询盘 Case ID/CRM、订单或 Ads 数据判断哪些搜索词和页面更接近业务成果。GSC 点击、展示和排名本身不是有效询盘或销售。
11. 季节性和重大变更：区分网站迁移、页面改版、URL 变化、广告投放、节假日、目标市场变化、追踪异常及搜索需求波动。无佐证的解释列为“待验证假设”。

三、提炼对新网站有用的结论
结合“旧网站已被 GSC 数据验证的有效主题”和“新网站的业务目标”，明确回答：
1. 新站最应该优先建设哪些产品分类页、产品页、行业解决方案页、国家/语言落地页、指南或博客？每项依据具体关键词和旧站 URL 数据。
2. 新站首页、顶部导航、分类层级、产品结构、内链和 CTA 应如何组织，才能承接有价值的搜索需求？对于 GSC 无法证明的 UX/转化判断明确标为建议。
3. 哪些旧站内容值得保留、更新、合并、重写或淘汰？给出旧 URL → 建议新 URL 映射草案及处理理由。
4. 哪些国家、语言、产品线需要独立关键词群及落地页？避免简单复制内容造成重复或市场意图冲突。
5. 新站上线前必须修复哪些抓取、收录、canonical、Sitemap、重定向和内容结构问题？
6. 旧站与新站如果并行运营，怎样划分关键词和页面所有权，减少搜索意图重叠？如果是迁移，如何保留有效 URL 和历史搜索资产？不要默认所有情况都做 301。
7. 哪些旧站结论不能直接套用到新站？说明品牌、地域、产品、用户意图和数据可比性限制。

8. 新站的 GSC 与 GA4/转化交叉验证方案：新旧属性配置、canonical 监控、关键着陆页自然搜索流量、真实有效询盘/订单关联。不要将 GSC 查询词强行归因到 GA4 的单个用户或订单。

【分析原则】
- 所有重要结论能追溯到 GSC 属性、搜索类型、查询条件、日期、国家/设备、具体页面或关键词。
- 事实、推断、假设、缺失证据和建议必须明确区分。
- 不编造 GSC 点击、展示、排名、收录、GA4 转化或真实客户询盘。
- 不将平均排名当成实时固定排名，不把 GSC 可见查询词求和当成全部查询总量；注明匿名化与行数限制。
- 不把“搜索相关性”写成“造成排名变化”，也不把点击当成询盘或销售。
- 如果追踪或数据质量存在严重问题，先给出可靠与不可靠结论的边界，再继续分析能完成的部分。
- 未经授权不修改 GSC、GA4、Ads、WordPress、GitHub 主分支、站点内容或生产配置。
- 过程中自行推进有权限且可验证的工作；只有缺少关键权限或业务信息确实影响结论时，才集中列出缺口。
