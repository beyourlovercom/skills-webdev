# S2-A — Isolated Windows Local build and authorized rebuild

**Scope:** Shared, public workflow. Verify live project facts first; generated site-specific `skills/site-builder-local/SKILL.md` in the destination project's repo takes priority. No credential, real customer data or private commercial report belongs here.

## Input
S1 and site profile, permitted old-site assets/screenshots/CMS exports, AGENTS.md, current project SHA and Local authorization.

## Procedure
1. Via the connected authorized BYL DC, inspect the **China Windows** target device, Local site instances, current PHP/Node/DB and repository checkout. Do not restart READY devices, Chrome, or touch other Local sites.
2. Distinguish actual old-site migration from simultaneously running two sites. Make an old-site audit (URLs, hierarchy, search/index structure, catalog, themes, plugin behavior, authorized art) and a site-build guidance report.
3. Allocate isolated Local site/database/ports. Implement with minimal diffs against current code, using allowed assets, real old-site page evidence, and data-led improvements. Do not infer UI from GA4.
4. Test templates, header/footer, menus, responsive site UX, browse/search, forms or cart/checkout as applicable, SEO routes, stock/variants if commerce. Store screenshot locations and exact commands/results, not imaginary PASS.
5. Produce Local site SHA, old/new URL map, deviations, unresolved defects and handoff to Dev.

## Gate
Actual Local functional/browser UAT PASS with all critical paths and project-specific business checks. Source-only tests are not browser PASS; Dev deployment requires appropriate authorization.

## Acceptance record
Always report host/device, evidence references, exact Git SHA, executed tests and PASS/FAIL/OPEN, approval state, no-production effects and next bounded action. Never confuse this Markdown document with an executable integration.
